# Database (Supabase)

Migrations follow the E-R design v2.2. Apply with the Supabase CLI (`supabase db push`) or,
for tests, on any Postgres 17 + PostGIS with `scripts/test_db.sh` (uses `tests/local_shim.sql`
to stand in for Supabase's `auth` schema and roles).

| Migration | Content |
|---|---|
| `…01_extensions` | PostGIS, pgcrypto |
| `…02_core_schema` | All tables; sandbox isolation via `(id, is_sandbox)` composite FKs; states as text + CHECK |
| `…03_auth_rls` | JWT hook (`cp_grants`), `has_permission()`, roles/permissions seed, RLS, `public_clusters`, `my_reports` |
| `…04_rpc_intake` | `issue_capture_nonce`, `submit_report`, `get_demo_status` |
| `…05_storage` | Buckets `raw`, `sandbox`, `public`; upload only to the nonce path |
| `…06_storage_nonce_check` | Upload check moved to `can_upload_capture()` (security definer): clients cannot read `capture_nonces` |

Seeds: `seed/catalog.sql` is generated by `scripts/sync_catalog.py` (do not edit);
`seed/ambato.sql` has the pilot city (approximate boundary, to be replaced by the official one)
and two unverified stakeholders.

Dashboard steps that SQL cannot do: enable `pg_cron` and `pg_net`, enable anonymous sign-ins,
point Authentication → Hooks → Custom access token to `public.custom_access_token_hook`, and
create the four Database Webhooks (INSERT on `reports`, `report_photos`, `resolutions`,
`dispatches`) to `POST {orchestrator}/webhooks/supabase` with `Authorization: Bearer <secret>`.

Applied from the API contract's open proposals (2026-10-24), pending confirmation:
`capture_nonces.purpose`, `resolutions.capture_nonce`, `photos.sha256` not unique (the
orchestrator flags reuse instead of failing the insert), the extra `NOT_VERIFIABLE_*` closure
statuses, and the permission `dispatches.respond`.
